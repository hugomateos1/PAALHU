2. Step 5 · Filter and stats on dishes

GET /api/dishes with query parameters
Reads?search=&category=&vegetarian=&available=. All optional, and they combine: ?search=naan&vegetarian=true.
Doessearch: case-insensitive match on name. category: one of starters, curries, vegetarian, rice, breads, desserts. vegetarian / available: only the text true or false (query values always arrive as text).
Answers200 with an array (possibly empty) · 400 { errors: [{ field, message }] } for a category outside the list or a flag that is not true/false.
WhereA query validator (e.g. validateDishQuery(query) in dishesValidator.js), the filtering in listDishes of the controller. Filtering happens on the server.
GET /api/dishes/stats
Answers200 { total, vegetarian, available, averagePrice, byCategory: { starters: 5, curries: 7, … } }, calculated on every request, never stored.
Watch outIn src/routes/dishes.js it must be declared before /:id (the comment marks the place); otherwise Express reads "stats" as an id.

3. Step 6 · Connect the pages to the API

Keep the HTML structure, classes and stylesheet; replace the data typed into the HTML with data from the API. Open the site only at http://localhost:3000 (npm start), never by double-clicking.

  1. public/js/api.js with apiRequest(method, path, body): the ONE place that calls fetch. It must check response.ok itself (fetch does not fail on 404 or 500) and return the data or the error list.
  2. One script per page in public/js/: find the element, ask the API, build one element per item with createElement + textContent, show them with replaceChildren.
  3. Every page must show a loading, an error and an empty state.
